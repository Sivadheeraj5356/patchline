Patchline
Self-maintaining API clients

An API provider ships a breaking change. Patchline diffs the old and new specs, flags affected call sites in the consumer codebase for the change patterns it supports, and drafts the migration pull request - deterministically, with no AI inference and no network calls. The demo below runs entirely in this page on a fictional billing API.

Choose the spec pair

The sample pair is the fictional Northwind Billing API v1.8.1 → v2.0.0. You can also paste your own pair in the same simplified JSON shape (paths, operations, parameters, request/response schemas).

Detected changes

Rule-based classification: removed endpoints and renamed fields are breaking; new endpoints and optional fields are additive.

Consumer codebase impact

The sample consumer is a 4-file JS app calling the old API. Patchline flags lines matching the detected breaking-change patterns and proposes safe mechanical edits. Removed endpoints are never auto-rewritten - they are flagged for manual review.

This is the artifact a provider's update agent would open against the customer repo - or what a neutral "Dependabot for APIs" service would file.
