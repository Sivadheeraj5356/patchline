Patchline
Self-maintaining API clients

An API provider ships a breaking change. Patchline diffs the old and new specs, flags affected call sites in the consumer codebase, and drafts the migration pull request - deterministically, no AI inference. It reads real OpenAPI 3.x documents (YAML or JSON, local $refs resolved) and can watch a live spec URL for changes. The sample below is a fictional billing API.

Choose the spec pair

The sample pair is the fictional Northwind Billing API v1.8.1 → v2.0.0. Paste any OpenAPI 3.x spec (YAML or JSON) - Local $refs, request bodies and content-wrapped schemas are resolved.

Detected changes

Rule-based classification: removed endpoints and renamed fields are breaking; new endpoints and optional fields are additive.

KindTypeDetail

Consumer codebase impact

The sample consumer is a 4-file JS app calling the old API. Patchline flags lines matching the detected breaking-change patterns and proposes safe mechanical edits. Removed endpoints are never auto-rewritten - they are flagged for manual review.

Draft pull request

A prepared draft only - Patchline never opens or sends PRs. A human reviews this markdown, applies the branch, and files the PR.


      

        
        
        
      

    

  


  

    

      
Watch a live API spec

      
Patchline polls the spec URL on the interval you set (minimum 60 minutes, with conditional requests so unchanged specs cost one cheap 304), saves a baseline, and records a diff event whenever the served spec actually changes.
