Features

Spec diffs that reach your code.

A version bump in an API spec is only the start. Patchline traces it into the places your product actually calls it.

<>

Diff the specs

Point Patchline at two OpenAPI specs. Changed fields, new endpoints and removals come out as a clean, reviewable list.

⌕

Find the blast radius

It scans your codebase for every usage the change touches - file, line and the exact field or endpoint involved.

✎

Draft the migration

Mechanical edits are drafted for you. Removed endpoints are never guessed - they are flagged for manual review. Rule-based, 68 tests.

How it works

From spec bump to draft in three steps.

/01

Compare two specs

Old spec in, new spec in. Patchline lists every change that could affect callers.

/02

Scan the codebase

Affected usages surface with file and line, so nothing breaks silently in production.

/03

Review the draft

Approve the drafted edits and handle the flagged removals yourself. You keep the final word.

Ship API changes without the archaeology.

Open source and rule-based - it drafts, you decide.
